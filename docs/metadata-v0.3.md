# Metadata triage v0.3

Add an independent `assess_document(staging, basename)` API, `forensic-maldoc assess` CLI, and `assess_staged_document` stdio tool. Keep the existing PDF and OLE reports stable. Hash the exact bounded snapshot. Match signatures before routing; compare only recognized extensions, allow encrypted Office wrappers to be considered possible OOXML, and report unknown/ZIP-only input without unpacking.

- **PDF:** follow `startxref` to a bounded, single classic cross-reference table and its trailer; confirm an `/Encrypt` target is a dictionary before claiming it is referenced, not that a password is required or encryption is operational. Read only whitelisted `/Info` key presence/type for an unencrypted supported layout. No text values, decryption, rendered content, XML, compressed tables, hybrid layouts or revision reconstruction. Unresolved pointers and unsupported layouts are explicit gaps. See [ISO 32000-1 §§7.5–7.6, §14.3](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/PDF32000_2008.pdf).
- **OLE:** inspect the root's `EncryptionInfo`/`EncryptedPackage` names as a pair. Nonempty declarations indicate a possible wrapper, empty declarations are lookalikes; do not validate crypto or infer that a legacy Office document is unencrypted. Separately inspect a bounded root `SummaryInformation` property stream for typed presence only. No document/macro/user content streams opened. See [MS-OFFCRYPTO](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-offcrypto/7ffe54c5-a76c-4eec-9690-dcc4640aac83) and [property identifiers](https://learn.microsoft.com/en-us/windows/win32/msi/summaryinfo-summaryinfo).
- **Rules:** emit stable IDs, evidence references and known limitations; no numeric risk score or malware verdict. Report separately what file type was observed, whether encryption was indicated, and what metadata layer and payload layer were not inspected. Unknown is not negative. Keep all structural/metadata parsing inside the existing budgeted sandbox. No password collection, authentication checks or guesses.

Acceptance: demonstrate mismatch, plain PDF Info, deceptive `/Encrypt` text, trailer reference, a bad xref reference, opaque Office property values, empty/incomplete Office wrapper markers, ZIP-only coverage, and equal structured results between Python, CLI and stdio. The [field book](wiki/Metadata-Encryption-Entropy.md) lists the structures and what they establish. The implementation reuses the existing pinned olefile API and the local xref lab's bounded-pointer pattern, without importing teaching code in production or adding a dependency.

## Verification

The 17-test Linux run passed with sandbox isolation and the pinned PDF tools enabled. It covered PDF reference and lookalike cases, unsupported revision linkage, unexpected property types, typed Office properties with values withheld, and empty, incomplete and nonempty wrapper-shaped fixtures. The same PDF assessment was compared over the Python API, CLI and stdio MCP. Ruff, source/wheel builds, and local links passed. Fixtures carry structural declarations, not real encrypted payloads, and no live files or novice/agent usability study were used.
